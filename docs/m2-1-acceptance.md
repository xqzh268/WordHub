## 三、遗留项（并入 M3.0）

| # | 严重度 | 事项 | 证据 |
|---|---|---|---|
| R1 | 中 | 审批卡缺路径、字数、差异 | 事件里有 `path`、`contentLength`，界面只渲染 `contentPreview`；覆盖已有文件时用户无法判断要改哪个文件。**我原先的断言 C2 有缺陷**：用“第二章”判断路径，而内容里恰好含这个词，因此巧合通过，需改为断言真实路径 |
| R2 | 中 | 越权被拒没有确定性的界面提示 | 界面上“权限类提示元素”为 0，用户能看到解释全靠模型自己说；一次越权请求里模型还重试了 3 次写入 |
| R3 | 中 | worker 1259 行；fallback 无法单测 | fallback 已实现但没有故障注入验证（报告已如实说明）；逻辑写在 worker 里，导致没法用 faux 单测。**M3 的协调器必须建在 `packages/runtime`，不能再往 worker 里加** |
| R4 | 低 | “测试连接”不发请求 | 保存密钥后显示“密钥已配置，可在下一次运行中使用”，填错的密钥同样显示成功；只设了环境变量时又显示“尚未配置密钥”，而实际能运行 |
| R5 | 低 | 过期卡与重载后的细节 | 卡片显示“已裁决：已过期”（措辞矛盾）；文案说“可重新发起”但没有按钮；重载后工具标签退回原始名（`doc.write` 而非“写入文档”） |
| R6 | 低 | 切换模型时思考强度默认取第一项 | 改为 `v4-pro` 后自动变成 `off`，应保持当前强度或取模型推荐值 |
| R7 | 低 | 夜间回归无密钥时静默通过 | 脚本在缺少密钥时 `exit 0`，工作流显示绿色但什么都没测；另需要你在仓库 Settings → Secrets 里添加 `DEEPSEEK_API_KEY` 才真正生效 |
| R8 | 低 | 两条断言偏松 | E2 第一分支只要聊天里出现“已中断”字样即通过；B3 靠整条回复文字匹配。应改为检查具体元素 |
| R9 | 待定 | 默认模型分配 | 保持 `flash/low`（我的测试里章节开头质量尚可，单次读写约 0.0005 美元），M4 做真实小说测试前恢复为 写手 `v4-pro/high`、评审 `v4-pro/max`，除非你另有决定 |

## 四、实测确认没问题的部分

- 工具链：读设定集 → 写章节，修订署名 `agent:writer`；越权写入被拦并记 `permission.denied`；需确认的写入批准前不落盘、批准后落盘、拒绝后不落盘。
- 重启：审批中强杀后事件序列完整（`approval.requested → run.waiting_approval → approval.expired → run.interrupted`），无遗留 `running`。
- 用量与费用与 pi-ai 返回值一致；每条回复显示。
- 密钥：加密保存、不落明文、不进事件。
- 上下文清单与界面“查看上下文”可用。
- GitHub CI 成功。
