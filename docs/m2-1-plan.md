**日期：2026-10-04**　依据：[m2-acceptance.md](m2-acceptance.md)（缺陷编号沿用）；上位文档 [m2-plan.md](m2-plan.md)、[p1-plan.md](p1-plan.md)。

M2 的构件基本都在，问题集中在“最后一公里”：真实模型一次都没有成功过。所以下一步不是新功能，而是**让 M2 真正跑通并有自动化兜底**，约 5 个工作日。完成后才进入 M3。

**退出标准**：`scripts/m2-live-e2e.mjs` 20/20 通过；新增的 faux provider 集成测试进入 CI；M2 计划里 7 条总体验收全部达成。

## 第 1 天：两个阻塞缺陷

先修这两个，因为它们让后面所有验证都没有意义。

**1.1 工具别名层（缺陷 1）**
- 逻辑名仍是 `doc.write` 等（AGENT.md、权限守卫、事件、界面标签都不变）。
- 在 Pi 适配层（`PiAgentHost`）做双向映射：发给模型时用 `doc_write`，收到工具调用时映射回逻辑名。顺便让这个目前无人使用的类真正承担“Pi 唯一边界”的职责。
- 注册时检测别名冲突（`doc.write` 与 `doc_write` 同时存在则报错）。
- 测试：对所有内置工具断言发给 provider 的名字匹配 `^[a-zA-Z0-9_-]{1,64}$`。

**1.2 错误不再被吞（缺陷 2）**
- 每次 `prompt / continue` 之后检查最后一条助手消息的 `stopReason` 与 `errorMessage`。
- 失败：追加 `run.error`（带原因）、`runs.status=failed`、界面显示红色错误卡与“重试”；被中止则走 `aborted`。
- 兜底：回复为空且用量为 0 一律按失败处理。
- 测试：用 faux provider 构造一个返回错误的场景。

**验收**：`m2-live-e2e` 的 A1–A6、B1–B2 在不打补丁的情况下通过。

## 第 2–3 天：审批与权限的可用性

**2.1 审批卡显示内容（缺陷 3）**：`approval.requested` 事件带工具名、相对路径、字数、前 N 行预览（限制大小）、相对当前文件的差异统计；卡片展示这些并支持展开完整差异。

**2.2 审批的重启语义（缺陷 4）**
- 渲染端先等后台确认再把卡片标为已裁决；失败要显示原因。
- 启动清扫把遗留的 `waiting_approval` 标为“审批已过期”，卡片给“重新发起”。
- 完整的跨重启恢复推到 M3（需要持久化待执行的工具调用与重建 Pi 上下文），这里在文档里明确写成限制。

**2.3 拒绝与越权的语义（缺陷 5、6）**
- 越权：不再 `terminate`，把拒绝原因作为工具错误结果交还模型，让它解释或改用 `propose`；群聊里同时显示“权限被拒：路径不在写入范围内”。
- 拒绝审批：把“用户拒绝了这次写入”作为工具结果交还模型，运行正常结束，不标失败、不显示红色错误。

**2.4 最小权限（缺陷 7）**：写入范围为空或未声明 ⇒ 禁止一切写入；AGENT.md 解析时给出明确提示；补测试（含项目级自建 Agent 的默认值）。

**2.5 纲领的写入路径（缺陷 11）**：实现 `bible.propose`（只生成候选修订，不直接替换），使默认入口 Agent 能产出大纲与人物档案的草案；`history.get` 同步补齐或从声明中移除。

**验收**：`m2-live-e2e` 的 B3、C2、C3、E2 通过。

## 第 4 天：自动化与结构

**3.1 faux provider 集成测试（缺陷 8）**：用 pi-ai 自带的 faux provider 脚本化模型输出，**确定性**地覆盖：工具调用、权限拒绝、需确认写入（批准 / 拒绝 / 过期）、API 错误、中止、用量记录、上下文清单与实际发给模型的消息逐项一致。

**3.2 让模拟模式走真实链路**：模拟模式改为“用 faux provider 驱动完整的 Agent 流程”，而不是绕过。这样 `test:desktop` 与 `test:m1:e2e` 才会触碰 M2 的产品代码，并可纳入 CI。

**3.3 结构整理（缺陷 9）**：worker 缩成只做消息路由；运行逻辑进入 `packages/runtime`，`RunService` 要么被使用、要么删除；Biome 覆盖 `apps/` 与 `scripts/`，限制单行长度。

**3.4 夜间真实模型回归**：新增一个定时 GitHub Actions 工作流，用仓库密钥跑 `m2-live-e2e`；PR 与 fork 不触发（拿不到密钥）。

## 第 5 天：界面与配置补齐

**4.1 用量显示（缺陷 12）**：每条回复下方一行“输入 / 输出 token · 费用”，并按会话汇总。
**4.2 上下文（缺陷 13）**：读取 `.wordhub/bible/*.md`（按文件名顺序、带预算）；“近期对话”改为可读的对话格式并去掉当前提示词；“查看上下文”弹层展示注入清单。
**4.3 Settings（缺陷 14）**：逐 Agent 的模型与思考强度选择（只列该模型支持的级别）、“测试连接”按钮；渲染端不再硬编码 Agent 元数据，改读运行时配置（消除缺陷 10 里的两份来源）。
**4.4 fallback 模型自动切换**：主模型报错且 Agent 配置了 `fallback` 时切换并记事件。

自定义 OpenAI 兼容服务可顺延到 M3 前后单独做，不阻塞。

## 需要你确认的一件事

**默认模型分配**。我们当初决定（[research/multi-agent-orchestration.md §7.2](research/multi-agent-orchestration.md)）：纲领与写手用 `deepseek-v4-pro / high`，评审用 `v4-pro / max`，编辑与观察者用 `flash / low`。现在的实现把**写手改成了 `flash / low`、评审降为 `v4-pro / high`**。

- 我的测试里 `flash / low` 写出的章节开头质量尚可，单次读写只需约 0.0005 美元，开发测试阶段更省钱。
- 但写手是小说质量的核心，且“质量 vs 成本”在 M4 做真实小说测试时会直接影响观感。

**我的建议**：开发测试阶段保留 `flash / low` 以节省成本，**但在文档里明确记为“开发期默认”**，并在 M4 前恢复为已定的分配。你若希望现在就恢复，告诉我即可。

## M3 的前提与调整

M2.1 完成后再启动 [m2-plan.md §三](m2-plan.md) 所列的 M3（协调器与群聊）。根据这次验收，M3 增加两项：

1. **持久化的审批**：把待执行的工具调用、参数与上下文落库，使审批能跨重启恢复并继续（M2.1 只做到“过期并可重新发起”）。
2. **“继续被中断的运行”**：中断与审批过期的运行都可以一键继续。

## 风险

| 风险 | 缓解 |
|---|---|
| 其他工具名在别的服务商下也有限制 | 别名层统一收敛到最严格的字符集；注册时校验 |
| faux provider 与真实模型行为有差异 | 夜间真实模型回归兜底；两类测试各司其职 |
| 模拟模式改造牵动现有 E2E | 先加新路径再切换，保持旧脚本可对照 |
| 审批差异预览体积过大 | 预览限长，完整内容按需从修订读取 |
