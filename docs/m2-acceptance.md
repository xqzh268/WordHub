## 二、M2：未通过

### 怎么验的

1. 干净安装后重跑全部命令（均绿）。
2. 通读 `packages/runtime`、worker、主进程、凭据与审批链路。
3. **新增真实模型端到端脚本** [scripts/m2-live-e2e.mjs](../scripts/m2-live-e2e.mjs)：真实 Electron + 真实 DeepSeek，提示词只描述意图、不出现工具名。覆盖读设定集并写章节、越权写入、审批批准 / 拒绝、审批中强杀重开、密钥泄露扫描。
4. 用 pi-ai 直接复现了失败原因，并用一个**临时本地补丁**（只在传给模型时把 `.` 换成 `_`，用后已还原）验证下游逻辑。

**为什么必须做第 3 步**：现有的 CI 与 `test:m1:e2e` 全部走“模拟模式”，而模拟模式**完全绕过** M2 的整条链路（AGENT.md、模型解析、工具、权限、审批、上下文）。所以所有绿灯都没有触碰 M2 的产品代码。

### 结果

| 状态 | 通过 | 说明 |
|---|---|---|
| 仓库当前提交 | **3 / 11** | 带工具的运行全部失败，脚本在审批环节前就超时 |
| 加临时补丁 | **15 / 20** | 链路跑通；5 项失败均为真实缺陷，见下 |

补丁下已确认可用的：读设定集并写入章节（有 `agent:writer` 署名的修订）、上下文注入清单记录、用量与费用记录（与 pi-ai 返回值一致）、越权写入被拦并记 `permission.denied`、审批批准后落盘、拒绝后不落盘、用户数据目录与项目文件夹中无明文密钥。

### 缺陷清单

| # | 严重度 | 缺陷 | 证据 | 修复方向 |
|---|---|---|---|---|
| 1 | **阻塞** | 工具名带点号，DeepSeek 返回 400 | pi-ai 直接调用：`doc.write` → `400 … does not match pattern '^[a-zA-Z0-9_-]+$'`，`doc_write` 正常。所有声明了工具的内置 Agent 在真实模型下一次都不会成功 | 逻辑名保持 `doc.write`（AGENT.md、权限、事件、界面标签不变），在 Pi 适配层做双向别名映射；加测试断言发给模型的所有工具名符合 `^[a-zA-Z0-9_-]{1,64}$` |
| 2 | **阻塞** | API 失败被记为“成功” | 事件日志：`run.usage 0/0` → `run.finished {ok:true, text:""}`，`runs.status=succeeded`，界面是空回复（见你发来的截图）。Pi 把错误放在最后一条助手消息的 `stopReason:"error"` 里，worker 从不检查 | 运行结束后检查 `stopReason / errorMessage`，写 `run.error` 并标 `failed`；界面显示错误原因与“重试”；用 faux provider 加测试；空回复且 0 用量时也按失败处理 |
| 3 | 高 | 审批卡是盲批 | 卡片正文只有“doc_write需要你的确认后才能继续”，看不到路径和内容（脚本 C2、C3 失败）。事件里只存了参数的键名 | 事件带路径、字数、前 N 行预览与相对当前文件的差异统计；卡片展示差异 |
| 4 | 高 | 重启后审批是“假批准” | 审批中强杀后重开：卡片恢复，点“批准”→ 卡片显示“已裁决：批准”，实际什么都没发生（后台报“该运行没有等待中的审批”，被渲染进程忽略），文件未写入，该运行在库里永远是 `waiting_approval`（启动清扫只处理 `running`）（脚本 E2 失败） | 先等后台确认再标记已裁决；启动时把遗留的 `waiting_approval` 标为“审批已过期”，卡片给“重新发起”。完整的跨重启恢复留到 M3（需要持久化待执行的工具调用） |
| 5 | 中 | 越权被拦后运行直接终止，回复为空 | `beforeToolCall` 返回 `terminate:true`，模型没有机会向用户解释或改用 `propose`；用户只看到一个失败的工具步骤（脚本 B3 失败） | 去掉 `terminate`，把拒绝原因作为工具错误结果交还模型；同时在群聊里加“权限被拒”提示 |
| 6 | 中 | 拒绝审批被记为运行失败 | 运行状态 `failed`，并追加 `run.error` | 拒绝是正常结果：把“用户拒绝”作为工具结果交给模型，运行正常结束 |
| 7 | 中 | 未声明写入范围等于不限制 | 探针：`write: write` 且无 `writeScopes`（或为 `[]`）→ 允许写 `任意目录/任意文件.md`。项目级自建 Agent 默认就是这种情形 | 最小权限：范围为空即禁止一切写入；加解析警告与测试 |
| 8 | 中 | M2 链路没有任何自动化覆盖 | 模拟模式绕过全部 M2 代码；运行时测试只测纯函数；无 faux provider 集成测试，验收标准里“上下文清单与请求一致”从未验证 | 用 pi-ai 的 faux provider 写确定性集成测试，并让模拟模式也走工具与审批 |
| 9 | 中 | 抽象未接入，worker 反而膨胀 | `PiAgentHost`、`RunService` 只定义、无人使用（grep 为空）；worker 从 196 行增至 371 行，35 行超过 200 字符；Biome 只覆盖 `packages/store` 与 `packages/runtime`，不含 `apps/`、`scripts/` | 让 worker 真正使用运行时包（别名映射正好放进 `PiAgentHost`），或删除死代码；Biome 覆盖全仓库 |
| 10 | 中 | 默认模型分配偏离已定决策 | 写手 `flash/low`（决策：`v4-pro/high`），评审 `v4-pro/high`（决策：`v4-pro/max`）；渲染端 `AGENTS` 常量与 AGENT.md 是两份来源 | 需你确认（见文末）；渲染端改读运行时配置 |
| 11 | 中 | “纲领”没有任何写入路径 | 纲领声明了 `bible.propose`，但 `builtin.ts` 未实现；它实际只剩 `bible.read` 与 `history.search`。它是默认入口 | 实现 `bible.propose`（只生成候选修订）或暂时从声明里移除 |
| 12 | 低 | 用量没有显示在界面 | 记录与 IPC 通道都在，聊天里没有渲染（脚本 A7 失败） | 每条回复下方显示 token 与费用 |
| 13 | 低 | 上下文层较粗糙 | 只读单个 `bible.md`（计划是 `bible/*.md`）；“近期对话”是原始 JSON 载荷，且包含当前这条提示词（重复）；没有“查看上下文”界面；token 估算为 `长度/2` | 读目录、可读的对话格式、去重、加预算、加弹层 |
| 14 | 低 | Settings 缺项 | 没有“测试连接”、逐 Agent 模型选择、fallback 切换、自定义服务（对方已如实标为未完成） | 见 M2.1 |

### 与自评和报告的出入

- “新增 packages/runtime / Pi 适配器 / 运行状态服务 / 接入”：`PiAgentHost` 与 `RunService` 并未接入任何调用方。
- “真实工具已经接上”：接上了，但真实模型从未成功调用过，因为缺陷 1。
- “思考流、工具流、用量元数据通道”：通道有，用量与上下文清单在界面上没有展示。
- “17 项单测通过”属实，但这些测试不覆盖 worker 的任何运行路径。

### 实测确认没问题的部分

- 权限守卫的判定与审批的最小闭环在真实模型下行为正确（补丁下）：越权被拒并留事件，批准前不落盘，拒绝后不落盘。
- 密钥：扫描用户数据目录与项目文件夹，不含明文；密钥只在主进程解密并经消息传给后台。
- 身份与模型记录：`run.started` 记录 `agentId / agentVersion / model / reasoning / mentions`。
- 用量：与 pi-ai 返回的 token 与费用一致，单次读写约 0.0005 美元量级（`deepseek-flash`）。
- 路径防护：见上。
