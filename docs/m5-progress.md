# M5 可编辑纸面进展

更新日期：2026-11-04。M5.1（可编辑纸面）、M5.2（导出）、M5.3（自建 Agent 表单）已完成。

## M5.3：自建 Agent 表单（已实现）

侧栏“新建 Agent”可用（需先链接写作文件夹）：弹出表单，保存为项目里的 `.wordhub/agents/<标识>/AGENT.md`，可用文本编辑器直接改、也能提交到版本库。侧栏里自建 Agent 的模型标签旁，点开后有“编辑这个 Agent…”，编辑页里可删除。

**表单字段**：显示名（也是 @ 提及的名字）、标识（小写英文，创建后不可改）、一句话描述、系统提示词、模型与思考强度、可读取的工具（读章节、读设定集、搜对话记录、查看历史详情、向我提问）与读取范围（章节/设定集/大纲）、写权限（只读 / 只提出修改 / 直接写入）、可写入范围（仅 `chapters/` 与 `.wordhub/bible/` 两个目录可选）、写入前是否先让我确认（默认勾选）、最大回合数（1–30）、头像字与颜色。写入类工具由“写权限 + 写入范围”自动推出，界面上不会出现自相矛盾的勾选组合。

**安全与一致性**（[custom.ts](../packages/runtime/src/agents/custom.ts)）：
- 校验：标识格式；不能与内置 Agent（纲领、写手、编辑、评审、史官）及 `all` 同名；显示名不含空白或 @、不与任何已有 Agent 重名；写权限、工具、范围必须自洽；模型必须存在且支持所选思考强度。
- 自建 Agent 不带质询、事实、摘要这类工作流内部工具，`canChallenge` 为空。
- frontmatter 由 YAML 库输出，冒号、引号、井号、正文里的 `---` 都不会串进 frontmatter；保存前用真实加载器解析一遍，字段不一致就拒绝保存。
- 写文件前检查 `.wordhub/agents` 路径链上没有符号链接；创建不能覆盖已有 Agent，更新和删除只作用于项目级 Agent，内置的拒绝。
- **项目级 Agent 不能顶替内置 Agent**（2026-11-04）：此前加载器允许项目里的 `.wordhub/agents/writer/AGENT.md` 覆盖内置写手，克隆来路不明的项目就可能悄悄换掉它的工具和写权限。现在同名文件加载时被忽略并报错，内置定义原样保留；侧栏会提示“有 N 个 Agent 配置没有生效：项目级 Agent 不能与内置 Agent 同名（writer），已忽略；请改个标识”（悬停看全部）。代价：之前靠覆盖定制内置 Agent 的用法失效。**我最初说“没有地方用到”是错的**：`product.test.ts` 的一个夹具（覆盖本就没起作用，已删除）、`m1-restart-e2e`（用覆盖写手来触发审批，已改用自建 Agent“抄写”）、`m2-live-e2e`（同样用覆盖写手来触发审批，已改用“抄写”）都依赖它，直到跑回归才发现。新增 3 项注册表单测和 2 项端到端断言。

**界面**：渲染端新增动态 Agent 注册表，自建 Agent 在侧栏、@ 名单、聊天消息、纸面作者色条里都有自己的名字和头像；已删除的 Agent 留在历史里时显示中性占位“?”，不再冒充纲领。另外统一去掉了界面错误提示里的 Electron 内部前缀（`Error invoking remote method…`），导出面板、服务商设置、表单都受益。

**真实模型验证**：表单创建只读“校对”：回答以自己的提示词要求的【校对员】开头，读到章节并指出预埋错别字，没有调用任何写入工具，被要求改文件时文件保持不变。表单创建可写“润色”（仅章节、写前确认）：改章节前出现审批卡，批准后“长案”改成“长安”且其余内容保留，修订记为该 Agent（`agent/polisher`）。让它写设定集（范围外）：权限层拒绝并记录事件，文件不变。重启后两个 Agent 仍在。

**测试里的一个教训**：第一次跑这一项时模型自己就拒绝了（“超出我的工具和职责范围”），文件没变，但权限层根本没被触发，那个检查因此失败。我把提示改成要求模型务必真的发起一次 `doc.write` 调用后重跑，这次是权限层拦截并留下事件。也就是说“范围外写入被拒”的真实证据来自第二次运行；第一次只说明模型会自觉拒绝。

### 未验证 / 局限

- 真实模型只各跑了 1 次，只用 flash，没有测其他模型或长提示词。
- 没有测 `只提出修改`（propose）级别的真实运行，也没有测写设定集范围（`bible.propose`）。
- 自建 Agent 只能被 @ 单独对话，不能加进写章/评审等内置工作流；也不支持多个 Agent 之间的质询。
- 项目 Agent 的模型引用如果后来被删除的服务商弄失效，侧栏会显示错误状态，没有专门的修复入口。
- 表单没有提示词模板或示例库，也没有导入/导出 Agent 的功能。
- 窄窗口下表单靠内部滚动，没有测过 600px 以下。

**手写/外部新增的 AGENT.md 不用重启**：上面 m2 的真实回归暴露了一个缺口——应用运行中新增 AGENT.md，侧栏不会重读，`@名字` 因此认不出来、消息被默认 Agent 接走。现在：发送以 `@` 开头、名字不认识的消息时先刷新一次 Agent 列表再路由；窗口重新获得焦点时也会刷新。新增 1 项端到端断言（运行中手写 AGENT.md → @ 它 → 侧栏出现并以它的名字回复）。同时修正了 m2 真实回归里一个过时的夹具（设定集文件名 `bible.md` 在 M4.2 之后不再是注入层），该脚本现在 22/22。

## M5.2：导出（已实现）

纸面章节栏的“导出”：范围可选当前章或全书（按章号顺序，第十章排在第二章之后），格式三选一。

| 格式 | 说明 |
|---|---|
| Word（.docx） | [docx](https://docx.js.org) 生成。默认正文宋体、标题楷体，西文 Times New Roman；正文小四（12 磅）、1.5 倍行距，段首缩进两个字符（随字号变化），章标题居中、每章另起一页；全书带书名页；粗体、斜体、引用、分隔线都保留 |
| 文本 UTF-8 | 章标题、段首两个全角空格、章间空两行、CRLF |
| 文本 GB18030 | 同上，按 GB18030 编码，给只认旧编码的软件；编码后再解码比对，有无法编码的字符就明确报错并点名，不静默替换成问号 |

**字体**：正文、标题字体各一个输入框，候选是预设（宋体、楷体、黑体、仿宋、微软雅黑）加上本机已安装的字体（Windows 用 .NET 的字体集合、Linux 用 fc-list；本机实测枚举出 316 个，约 0.7 秒），也可直接手填字体名。字号、行距可调，选择记在本机。字体名只写入文档、不嵌入字体文件：对方电脑没有该字体时 Word 会自动改用相近字体。字体名会校验（拒绝控制字符与 `< > " &`），字号限 6–72 磅、行距限 1–3 倍。

保存位置由系统保存对话框选择，先写临时文件再替换，失败不留下半截文件；渲染端不能指定输出路径。取消对话框不产生文件也不报错。

## M5.1：编辑、保存、撤销与冲突保护（已实现，已验证）

纸面默认是阅读视图（保留作者色条和评审质询标记）；点“编辑”进入 Tiptap/ProseMirror 编辑，点“完成”或按 Esc 退出。Markdown 仍是章节真相源。

**编辑器与 Markdown 转换**（[markdown.ts](../apps/desktop/src/renderer/state/markdown.ts)）
- 只开放标题（1–3 级）、段落（段内换行）、粗体/斜体、单行引用、分隔线。列表、表格、链接、代码块等按原样当作普通文字保留，往返不改一个字。
- 作者键入的字面 `*`、`_`、`\` 会转义，重开后不会变成强调。回车产生的空段落不写进文件。
- 章节含会被改写的写法（如 `__粗体__`、多行引用）时，“编辑”按钮禁用并说明原因，宁可不让改也不静默改写原文。
- 保存的是规范 Markdown：多余空行会被收拢，结尾补换行。

**保存、冲突与撤销**
- 自动保存（输入停止 1.2 秒后），也可点“完成”立即保存；点“完成”时若保存正在进行会等它结束，写不进去（冲突、Agent 运行中、出错）就留在编辑状态，不丢稿。
- 保存走既有受控写盘通道（临时文件 → 校验 → 原子替换 → revision），作者记为 `user`，带读取时的内容哈希作基线。基线固定在进入编辑时的版本，外部变化不会悄悄换掉它。
- 磁盘被外部或 Agent 改过时拒绝覆盖，提示“保留我的版本 / 载入新版本 / 查看差异”。保留我的版本会把外部版本留在修订里。
- “撤销”以新 revision 回到上一版本。
- 编辑中章节导航、定稿按钮被锁定，Agent 写入或“第N章”提示不会把纸面带到别的章节；任何 Agent 运行期间纸面只读，并显示原因。
- 渲染端写入/撤销只允许 `chapters/` 下的 Markdown 文件（[dispatcher.ts](../packages/runtime/src/runs/dispatcher.ts) 的 `assertChapterPath`）。

## 开发中发现并修复的缺陷

1. **既有章节上的第一次编辑会被误判为冲突（核心缺陷）**。磁盘上已有、但还没有修订记录的文件（新链接的项目、作者自己放进去的稿子），第一次写入会被当成“外部修改”拒绝，即使调用方基于的正是磁盘上这一版。现在 `expectedHash` 与磁盘一致时放行，原文照样存成修订，可撤销；过期、为空或缺失的 `expectedHash` 仍被拒绝（[files.ts](../packages/store/src/files.ts)，两个新单测）。
2. 刚载入章节就显示“待保存”，进入编辑后会立刻自动保存一次不含修改的内容。现在以内容是否与已落盘一致为准判断是否有修改。
3. 阅读视图原先被隐藏，作者色条和质询标记丢失，已恢复。
4. 立即点“完成”会丢掉未触发自动保存的输入；保存进行中点“完成”被忽略。均已修复并有端到端覆盖。
5. 一键切换全部角色模型时并发读改写同一文件会互相覆盖（见[多服务商验收](providers-acceptance.md)），已改为顺序提交。
