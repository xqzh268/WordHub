# M5 可编辑纸面进展

更新日期：2026-11-03。M5.1（可编辑纸面）和 M5.2（导出）已完成，M5.3（自建 Agent 表单）尚未开始。

## M5.2：导出（已实现）

纸面章节栏的“导出”：范围可选当前章或全书（按章号顺序，第十章排在第二章之后），格式三选一。

| 格式 | 说明 |
|---|---|
| Word（.docx） | [docx](https://docx.js.org) 生成。默认正文宋体、标题楷体，西文 Times New Roman；正文小四（12 磅）、1.5 倍行距，段首缩进两个字符（随字号变化），章标题居中、每章另起一页；全书带书名页；粗体、斜体、引用、分隔线都保留 |
| 文本 UTF-8 | 章标题、段首两个全角空格、章间空两行、CRLF |
| 文本 GB18030 | 同上，按 GB18030 编码，给只认旧编码的软件；编码后再解码比对，有无法编码的字符就明确报错并点名，不静默替换成问号 |

**字体**：正文、标题字体各一个输入框，候选是预设（宋体、楷体、黑体、仿宋、微软雅黑）加上本机已安装的字体（Windows 用 .NET 的字体集合、Linux 用 fc-list；本机实测枚举出 316 个，约 0.7 秒），也可直接手填字体名。字号、行距可调，选择记在本机。字体名只写入文档、不嵌入字体文件：对方电脑没有该字体时 Word 会自动改用相近字体。字体名会校验（拒绝控制字符与 `< > " &`），字号限 6–72 磅、行距限 1–3 倍。

保存位置由系统保存对话框选择，先写临时文件再替换，失败不留下半截文件；渲染端不能指定输出路径。取消对话框不产生文件也不报错。

### 修复的界面问题

导出面板首版出现三处错乱（用户截图指出）：面板被纸面盖住、导出按钮图标与文字上下叠放、面板里的按钮被压成方块。根因是章节栏里给“上一章/下一章”箭头写的 `.chapter-nav button` 规则（固定 28px 方形）波及了定稿、导出及面板内的所有按钮，且章节栏没有高于纸面的层级。已把箭头样式限定到直接子按钮、章节栏提升层级、面板改为相对整条章节栏定位。随后又发现窄窗口下面板被纸面区域左侧裁切，以及编辑工具栏（编辑/撤销/已保存）被挤成竖排换行，均已修复并加了断言。

### 未验证 / 局限

- **没有用 Word 或 WPS 打开过生成的 DOCX**：只验证了解压后的 XML 内容和 docx 库的输出，实际渲染效果（字体回退、分页、缩进的观感）需要人工打开确认。
- 字体只能写名字，不嵌入；未检查所选字体是否真的支持全部汉字（生僻字可能显示为方框）。
- 字体枚举只在 Windows 上实测过；Linux 的 fc-list 路径和 macOS（无枚举，只有预设和手填）没有测试。
- 不支持封面、页眉页脚页码、目录、EPUB；列表、表格、链接在导出里按普通文字处理。
- 编辑面板窄窗口下的版面断言我没有在旧样式上验证它确实会失败（旧样式的错乱由截图确认）。

## M5.1：编辑、保存、撤销与冲突保护（已实现，已验证）

纸面默认是阅读视图（保留作者色条和评审质询标记）；点“编辑”进入 Tiptap/ProseMirror 编辑，点“完成”或按 Esc 退出。Markdown 仍是章节真相源。

**编辑器与 Markdown 转换**（[markdown.ts](../apps/desktop/src/renderer/state/markdown.ts)）
- 只开放标题（1–3 级）、段落（段内换行）、粗体/斜体、单行引用、分隔线。列表、表格、链接、代码块等按原样当作普通文字保留，往返不改一个字。
- 作者键入的字面 `*`、`_`、`\` 会转义，重开后不会变成强调。回车产生的空段落不写进文件。
- 章节含会被改写的写法（如 `__粗体__`、多行引用）时，“编辑”按钮禁用并说明原因，宁可不让改也不静默改写原文。
- 保存的是规范 Markdown：多余空行会被收拢，结尾补换行。

**保存、冲突与撤销**
- 自动保存（输入停止 1.2 秒后），也可点“完成”立即保存；点“完成”时若保存正在进行会等它结束，写不进去（冲突、Agent 运行中、出错）就留在编辑状态，不丢稿。
- 保存走既有受控写盘通道（临时文件 → 校验 → 原子替换 → revision），作者记为 `user`，带读取时的内容哈希作基线。基线固定在进入编辑时的版本，外部变化不会悄悄换掉它。
- 磁盘被外部或 Agent 改过时拒绝覆盖，提示“保留我的版本 / 载入新版本 / 查看差异”。保留我的版本会把外部版本留在修订里。
- “撤销”以新 revision 回到上一版本。
- 编辑中章节导航、定稿按钮被锁定，Agent 写入或“第N章”提示不会把纸面带到别的章节；任何 Agent 运行期间纸面只读，并显示原因。
- 渲染端写入/撤销只允许 `chapters/` 下的 Markdown 文件（[dispatcher.ts](../packages/runtime/src/runs/dispatcher.ts) 的 `assertChapterPath`）。

## 开发中发现并修复的缺陷

1. **既有章节上的第一次编辑会被误判为冲突（核心缺陷）**。磁盘上已有、但还没有修订记录的文件（新链接的项目、作者自己放进去的稿子），第一次写入会被当成“外部修改”拒绝，即使调用方基于的正是磁盘上这一版。现在 `expectedHash` 与磁盘一致时放行，原文照样存成修订，可撤销；过期、为空或缺失的 `expectedHash` 仍被拒绝（[files.ts](../packages/store/src/files.ts)，两个新单测）。
2. 刚载入章节就显示“待保存”，进入编辑后会立刻自动保存一次不含修改的内容。现在以内容是否与已落盘一致为准判断是否有修改。
3. 阅读视图原先被隐藏，作者色条和质询标记丢失，已恢复。
4. 立即点“完成”会丢掉未触发自动保存的输入；保存进行中点“完成”被忽略。均已修复并有端到端覆盖。
5. 一键切换全部角色模型时并发读改写同一文件会互相覆盖（见[多服务商验收](providers-acceptance.md)），已改为顺序提交。

## 未验证 / 未做

- 真实模型只验证了“写手读取作者改过的内容”一次，没有覆盖作者改稿后继续写下一章或评审；也没有长章节（数千字）的编辑体验和性能测试。
- 作者色条在编辑模式下不显示；编辑后用户修订不在阅读视图里以色条标出。
- 撤销只有“回到上一版本”，没有版本列表或差异预览；“查看差异”只是并排显示两份全文，不是逐段差异。
- 冲突保护只在保存时检测，没有在编辑期间实时提示（通过自动保存或点“完成”才会发现）。
- 专注模式、字数之外的统计（目标字数等）未做。
- M5.3 自建 Agent 表单未开始；M4 遗留的三个间歇性问题仍搁置。
