# 多服务商与模型选择：验收记录（2026-10-29）

范围：设置页“服务商与密钥”“模型分配”，以及后台进程的密钥同步、自定义服务商注册、价格估算。只验收 **OpenAI 兼容（Chat Completions）** 一种自定义协议；Anthropic Messages 与 OpenAI Responses 代码路径存在，但没有密钥，**未验证**。

## 本轮修复与补充

| 项 | 内容 |
|---|---|
| 史官（原观察者） | 保留角色与功能；显示名改为“史官”（内部 id 仍为 `observer`，无需迁移）。恢复在“模型分配”里可选模型；仍不出现在侧栏与 @ 名单（定稿的内部步骤）。 |
| 发送队列 | 单条消息发送失败不再卡死后续所有请求，等待响应的请求会被拒绝。 |
| 密钥同步次序 | 后台进程先完成 `credentials.sync`，之后到达的请求才开始处理。 |
| 密钥解密 | 主进程缓存解密结果，保存/删除密钥时失效，不再每条消息都解密。 |
| 一键切换 | “全部角色改用…”。过程中发现并修复一个并发覆盖问题：并发写同一个 `agent-models.json` 只剩一项生效，改为顺序提交。换模型时思考强度尽量沿用，不支持则取接近的高档（不再退回 off）。 |
| 测试连接 | 可选测试用模型；默认选已知价格里输出最便宜的，不再取目录第一个。 |
| 模型筛选 | 模型分配支持按名称/ID 筛选，当前已选项始终保留。 |
| 自定义服务商 | 可编辑（ID 不可改，已保存密钥保持不变）；每个模型可填上下文长度、输入/输出价格、是否支持思考。 |
| 价格策略 | 用户填了就按填的算（`user`）；没填先按模型 ID 在 Pi 目录里找同名模型作参考（`catalog`，含 `厂商/模型` 的后缀匹配）；都没有标为 `unknown`：设置页逐个点名“价格未知”，运行前预估里写明该模型费用未计入。 |
| 旧字段清理 | 删除请求里已无用的 `apiKey` 字段与相关传递；密钥只经主进程同步到后台的凭据存储。 |

### 真实模型验收（deepseek-flash，约 0.015 美元）

应用进程环境里**没有任何 DeepSeek 密钥**；只在设置页添加自定义服务商 `ds-proxy`（指向 DeepSeek 的 OpenAI 兼容接口，模型 `deepseek-flash`，勾选“支持思考”），并在界面里填入密钥。

1. 内置 DeepSeek 显示“尚未配置密钥”；自定义服务商的价格自动参考目录，不提示价格未知。
2. 保存密钥 → 测试连接成功。
3. “全部角色改用…”后，纲领、写手、编辑、评审、史官全部指向 `ds-proxy/deepseek-flash`。
4. “写第一章”（写手→编辑→评审）正常收尾，章节 875 字符；用量 11 条，按目录价格计费 $0.01476。
5. “定稿”完成并记录，史官抽取 13 条待确认事实并写了摘要。
6. 需要审批的写入：审批中强杀整个应用，重开（无环境密钥）后审批卡仍在，批准后用已保存的密钥恢复并正常收尾。

局限（如实说明）：
- 事件日志的 `run.started` 不记录服务商，所以“未用内置 deepseek”靠“应用进程没有该密钥，运行成功即说明走的是自定义服务商”来证明，不是靠事件字段。
- 自定义服务商指向的是 DeepSeek 本身，验证了协议和密钥链路，没验证第三方网关的兼容差异（工具调用、思考字段等）。
- Anthropic Messages / OpenAI Responses 未验证。
- 价格目录匹配只按模型 ID，网关对同名模型加价时需要用户自己填。
