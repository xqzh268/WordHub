## M4.1：纲领分层问答

实现位于[novel/intake.ts](../packages/runtime/src/novel/intake.ts)，界面通过群聊表单卡回答。

- 首句作为题材梗概；能从“主角是/为/叫/：”等简单表达提取主角。
- L1必答：梗概、主角、核心冲突。L2可跳过：世界、视角与基调、主题、读者、章数、必含和禁写内容。
- 修改前面的回答会清除后续回答并重新提问；问答状态由事件重放恢复。
- 最后一题回答后，纲领Agent（`planner`，默认v4-pro/high）在后台根据全部回答生成大纲（含逐章）、人物档案、设定词典、文风基准四份草稿（[novel/draft.ts](../packages/runtime/src/novel/draft.ts)），以“纲领草稿”卡展示，可展开阅读；作者没给、模型补全的条目以“（建议）”标注。
- 用户点“确认并写入”后才经受控写盘落到`.wordhub/bible/`（四份文档+`writing-plan.json`）；草稿阶段不写任何文件。可点“重新生成”再来一版，修改前面的回答会让旧草稿作废。草稿生成期间不允许确认。
- 模型输出格式不对会重试一次；仍失败或没有密钥时回退为按回答直接整理的基础版本，并在卡片上写明原因，不会卡死流程。草稿经事件（`intake.draft.started/failed/ready`）持久化，重启可恢复。
- 验证：单测（解析、重试、回退、重新生成、生成期间禁止确认、投影与渲染端恢复）；`npm run test:m4:draft`为真实DeepSeek的Electron验收（13项）。

草稿里模型补全条目的“（建议）”标记按用户决定保留并写入文件。L2随机建议、“用户×文体”偏好记忆仍待补齐；模型补全的内容质量依赖提示词与输入，仍需在M4.7用真实创作评估。

## M4.2：固定顺序上下文

实现位于[context/project.ts](../packages/runtime/src/context/project.ts)和[ContextBuilder](../packages/runtime/src/context/builder.ts)。存在且在Agent读取范围内的内容按以下顺序注入：

| 层 | 来源 | 当前每层预算 |
|---|---|---:|
| 本章大纲行 | `.wordhub/bible/outline.md`中匹配章号的行 | 1,200估算token |
| 设定词典 | `.wordhub/bible/setting.md` | 1,800估算token |
| 人物档案 | `.wordhub/bible/characters.md` | 1,800估算token |
| 上一章文本窗口 | 当前修订快照，缺失时读取`chapters/`文件 | 400估算token |
| 文风基准 | `.wordhub/bible/style.md` | 800估算token |

总预算默认为12,000，按字符数除以2粗估token，并逐层裁剪；系统提示、工具声明和格式标记不属于准确的供应商token计数。缺失或无权限的层不会注入。“查看上下文”显示层、来源、估算用量与预算，目前没有展示每层完整正文。

已补齐并通过确定性测试：

- 人物档案按本章大纲和用户请求筛选，始终保留主角段落；未匹配到结构化人物标题时回退全文，避免静默丢失人物。
- 上一章取500–800字，并从句号、问号、感叹号、分号或换行后的完整边界开始；层预算为400估算token，构建器不会再从窗口前端截断掉真正的结尾。
- 大纲匹配兼容阿拉伯/中文复杂章号、有序列表、加粗标题和多行章节段落；章节文件名解析也支持带目录的历史artifact路径。
- 新增faux实际请求验收，检查模型收到的内容包含本章大纲、筛选人物、完整句尾窗口和文风层，并排除无关人物与后续章节伏笔。

真实模型注入仍需在下一次有密钥的 M4.7 回归中复核；本轮不做评审 pro/max 对照。

## M4.3：确定性编辑检查

纯函数[checkEditorText](../packages/runtime/src/editor/checks.ts)不调用模型、不改正文，返回`ok`、`metrics`和`violations`。

| 检查 | 当前定义与默认行为 |
|---|---|
| 字数 | 计汉字、ASCII字母与数字；不计标点和空白。函数支持`minWords/maxWords`，产品默认未设上下限 |
| AI腔词 | 按固定负面词表做字面匹配，记录各词出现次数；是文风提示，不能判断文字是否由AI生成 |
| 对话占比 | 配对中文引号、直角引号或英文双引号中的计数字符，占全文计数字符的比例；默认提示线为65% |
| 连续四字成语 | 在内置短词表中匹配相邻短语，间隔至多两个字符时归为连续段；超过两段提示 |

协调器在`edit`任务成功后读取章节修订，追加`editor.check`事件，记录任务、文件、修订ID、指标和问题；聊天实时显示及历史重放均投影为提示。当前优先选择本编辑运行最后一次`file.updated`路径；没有该事件时从当前章节修订中回退选择，并非全项目逐章检查。

编辑Agent的职责已改为语病、重复、句式、标点与语言润色，写权限限制为`chapters/**`，评审负责提出设定与正文之间的异议。

当前边界：

- 检查仅提示，不将问题自动改为失败任务，也不自动重试或阻断后续评审。
- 产品未接项目级规则文件或设置表单；规则覆盖只在检查函数接口支持。
- AI腔与成语检查是有限词表规则，对话占比是引号启发式；引述、嵌套引号与跨段对话需要更完整的规则和样例。
- “只改文字、不改情节”由角色指令与文件权限约束，尚无语义差异校验或真实润色情节保持验收。
- 五项检查单测、写手→编辑faux工作流断言及存储投影测试已加入常规测试。

## M4.4：评审清单

- `challenge.raise`必须选一致性分类（`timeline`时间线、`character`人物塑造、`fact`基本事实、`commonsense`常识、`style`风格），并用`citations`逐字引用出处原文；时间线/人物/基本事实类需引用矛盾的**两端**（正文＋设定，或正文＋另一章），常识/风格至少引用正文问题处。实现在[tools/citations.ts](../packages/runtime/src/tools/citations.ts)：引文必须逐字出现在出处文件（`chapters/`或`.wordhub/bible/`）里，忽略空白与引号差异，省略号两侧分段核验；对不上就返回工具错误，质询不成立。这是“引用设定原文与出处”的确定性保证，也是压制评审幻觉误报的主要手段。
- 评审提示词改为逐类核验清单；“写一章”工作流为写手→编辑→评审（每章写完立即评审）。
- 质询卡显示分类标签与引文。
- 大纲按章节标题取整段（[context/project.ts](../packages/runtime/src/context/project.ts)的`outlineForChapter`）：模型生成的大纲把目标/事件/悬念写在标题下的列表里，旧逻辑只取标题行。
- 评测[scripts/m4-review-eval.mjs](../scripts/m4-review-eval.mjs)：设定集只陈述事实，五类预埋矛盾各一章＋干净章节。2026-10-22以**deepseek-flash**（测试统一用flash）跑3轮：检出15/15、分类命中15/15、干净章节误报0/3、出错0/3，通过。注意这是flash的结果，产品默认评审是v4-pro/max，未做同口径对照。
- 未做：“核验问题隔离作答”（每类单独起一个评审任务、各自只看相关上下文）。当前用单次评审＋确定性引文核验替代，成本与时延更低；若多轮评测显示漏检或误报偏高，再拆成按类并行任务。

## M4.5：史官与事实表

- 史官只做定稿时的整理，不对话：用`fact.propose`提出带逐字锚点的待确认事实（`character_state`人物状态、`term`新名词、`foreshadow`伏笔、`event`关键事件），用`chapter.summarize`写章节摘要。事件`fact.proposed/confirmed/rejected`、`chapter.summary`进入事件日志，由[contracts/facts.ts](../packages/contracts/src/facts.ts)投影（最后一次决定为准，可改判）。

- 评审与写手的上下文新增“已确认事实”“章节摘要”两层，仅含**当前章之前**的章节；未确认与已驳回的不进入。
- 史官已从侧栏与@名单移除，作为“定稿”的内部步骤保留（设置里仍可分配模型）。
- 审批门槛修正：只有真正写文件的工具需要审批，`fact.propose`等系统记录类工具不触发审批。

## “AI味”（文风）

用户反馈生成文字有“零散破碎、‘不是……而是……’、喜欢排列数据”的机器味。分析：一部分是我们自己放大的（纲领生成的文风基准要求“短句为主、多用动作暗示心理”，写手照做就写碎），一部分是大模型写中文的通病。处理分四层，不新增“润色”Agent（与编辑职责重叠）：

1. **可数指标**：[editor/style-metrics.ts](../packages/runtime/src/editor/style-metrics.ts)——碎句连串、“不是……而是……”、清单式并列、精确数字密度、比喻词密度、句长统计及综合“指数”（每千字可疑处）。是**相对指标**，用于比较不同提示词/流程的产出，不是“是否AI所写”的检测器；`node scripts/style-report.mjs 文件.md`可查看。`editor.check`事件携带这些指标。
2. **从源头修**：纲领生成文风基准的提示词不再要求“短句为主”，改为长短句交错、有因果衔接、少堆细节/计数/比喻；写手提示词加入同类写法要求。
3. **编辑针对性改写**：协调器把静态检查标出的句子附在编辑节点任务里，要求只改表达、不改情节。
4. **人工盲评**：[scripts/style-blind-eval.mjs](../scripts/style-blind-eval.mjs)用A现状 / B改提示词 / C再加编辑改写三个版本写同样章节，打乱编号输出`artifacts/style-eval/blind.md`供人打分，`key.json`为对应关系，并输出各版本的静态指标。结论以人工盲评为准。

### 第一轮盲评结果（2026-10-29）

三个版本各2轮×2章=12份样稿，打乱编号，用户逐份打分（1–5，不看版本）：

| 版本 | 内容 | 平均分 | 静态指数 |
|---|---|---|---|
| A | 最初版本 | 3.62 | 1.11 |
| B | 改提示词 | 3.62 | 0.17 |
| C | 再加编辑按静态清单改写 | 3.50 | 0.00 |

- **静态指标明显改善，人的评分没有变化**（每组仅4份，噪声大，差异不显著）：第一~三层只解决了指标能量化的那部分（碎句、清单并列、数字/比喻密度），没有改变读者的整体感受。
- 用户同时指出，12份样稿共有的“AI味”在**篇章层面**，与版本无关：①人物档案里的标志性小动作被逐条执行（“某也是为你好”、转盏沿、指甲、算珠……几乎每份都全套出现）；②第二章是同一套模板（走访甲乙丙丁、每家一条线索、最后有人说“当年不是盗杀”、约明夜三更），6份全是；③开头（“等最后一声鼓落定才抬脚”）和结尾（手攥着不松、格言收尾）套路化。
- 用户还把12份样稿按“上一章→下一章”正确配成6对，说明同一轮产出的前后章风格高度同质。
- 结论：这些重复来自大纲与人物档案本身，不是“改写”能解决的。第二轮改在源头（见下）。

### 第二轮：去篇章层套路

- 纲领生成提示词：逐章大纲要求相邻章节功能有变化（避免“走访—线索—约定”模板），全书至少一次关系/情感推进、一次反转、一次主角失败或付出代价，章末悬念形式多样；人物档案里习惯性小动作最多1–2个并注明“只是倾向，每章同一动作最多一次，可以不用”，惯用手等硬设定单列。
- 写手提示词：习惯小动作只是备选，同一动作每章最多一次；不用固定起手和“手没有松开/格言”式收尾，章末停在具体场面；每章侦探式细节特写不超过两处。
- 盲评变体：B（第一轮改动，对照）对D（去篇章层套路），各2轮×2章，D用新提示词重新生成整套设定。

### 第二轮盲评与交叉实验（2026-10-29，flash）

第二轮B对D：用户平均分 B 3.12、D 4.12（+1.0）。但D的设定（人物、案情）是整套重新生成的，故事本身就能暴露版本，不是真盲评，且“写手提示词”与“设定”两个因素混在一起。因此补了交叉实验：E＝新写手提示词＋旧设定，F＝第一轮写手提示词＋D的新设定（每格2轮×2章，仍能凭设定认出，用户只按读感打分）。

| | 旧设定（旧纲领提示词生成） | 新设定（新纲领提示词生成） |
|---|---|---|
| 旧写手提示词 | B 3.12 | F 3.88 |
| 新写手提示词 | E 3.50 | D 4.12 |

- **设定（即纲领生成提示词）的效应约 +0.7**（旧写手下 F−B=+0.75，新写手下 D−E=+0.62）；**写手提示词的效应约 +0.3**（旧设定下 E−B=+0.38，新设定下 D−F=+0.25）。每格仅4份、用户打分波动约±0.5、三轮打分尺度略有漂移，只能说“设定的影响大于写手提示词”，不能说写手提示词无效。
- 用户逐项标记的三类套路：**走访模板**跟着旧大纲走（旧设定的两份第二章仍是“走访—有人说当年不是盗杀—约时间”，新设定的没有），写作提示词去不掉；**小动作**也主要跟着人物档案走（旧设定里韩敬的全套动作照出，新设定里韩勖“慢翻册子、刮碗沿”的骨架两轮几乎相同）；**开头结尾套路**两套设定下都有、不明显由哪边决定。
- 新设定仍有的残留：同一人物的小动作在不同章节反复出现（已在写手提示词加入“上一章用过的小动作本章不要再用”，尚未评测）；不同轮次的第二章骨架趋同（大纲带来的趋同）。
- 结论：“AI味”的主因在**设定生成**——人物档案写成可逐条执行的动作清单、大纲给出固定节奏——而不在最后的润色。后续若继续优化，应继续改纲领生成提示词（以及考虑多生成几版设定供用户挑选/混合），而不是加更多改写环节。

多服务商与模型选择的验收见 [providers-acceptance.md](providers-acceptance.md)。
