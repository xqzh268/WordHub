## 一、chinese-novelist-skill 深读【实】

来源：[PenglongHuang/chinese-novelist-skill](https://github.com/PenglongHuang/chinese-novelist-skill)（SKILL.md、`references/flows/` 8个文件及模板、脚本）。

### 1.1 分阶段流程

- **Phase 0 初始化**：读 `user-preferences.json`；**快捷入口**——首句信息够用时直接给出提取结果，提供"直接规划 / 确认修改 / 仍走问答"；扫描 `02-写作计划.json` 中 `in_progress`/`validating` 的项目，询问是否续写。
- **Phase 1 三层问答**：核心定位 → 深度定制 → 标题生成。
- **Phase 2 规划**：人物档案、大纲、文风基准、写作计划JSON，用户二次确认。
- **Phase 2.5**：选择写作模式。
- **Phase 3 "疯狂创作"**：全程不向用户确认。
- **Phase 4 自动校验修复**：最多3轮。

### 1.2 首轮提问（分层）

每题给热门选项 + "自由描述"；L2 每题多一个"🎲随机生成"；偏好匹配项排前并标⭐。

- **L1 必答**：Q1 题材与创意概要（7选项）；Q2 主角类型（单男/单女/双主/群像）+ 追问职业身份、核心性格（6原型）、关键配角；Q3 核心冲突（7类）+ 内在驱动力（复仇/爱/责任/好奇/生存/野心）。答完展示摘要，静默写入偏好。
- **L2 可跳过**：Q4 世界观（奇幻/科幻"强烈推荐"）；Q5 视角与基调；Q6 主题；Q7 目标读者与风格参考作者；Q8 章节数（10/15/20/30/50）与特殊要求（必含/禁写/字数）。完成后展示完整配置，可"回到QX"修改。
- **L3 标题**：3个候选（跨题材5个），各用不同技巧；重生成超5轮提示自填。

### 1.3 产出物

目录 `./chinese-novelist/{时间戳}-{书名}/`：
- `00-人物档案.md`：主角/反派/配角；年龄职业、外貌、性格核心、价值观、最大恐惧、致命缺陷、内心渴望、背景、MBTI、说话风格与口头禅。
- `01-大纲.md`：8列章节表（章节、标题、核心事件、承接上章、章首引子类型、悬念钩子、出场人物、场景列表）；全书悬念线（主线/支线/终极揭秘）；**设定词典**（名词、首现章节、读者已知、完整真相、计划揭示）；章节摘要区（每章写完追加300–500字）。
- `02-写作计划.json`：version、novelName、totalChapters、minWordsPerChapter、status（planning/in_progress/validating/completed）、writingMode、chapters[]（chapterNumber、title、filePath、status、wordCount、wordCountPass、retryCount）。
- `03-文风基准.md`：文风指纹（对话占比35–45%、短句为主）；2段500–800字基准段落；AI腔负面清单；"本书校准段落"（第1章定稿后回填，作为后续文风锚点）。
- 章节文件：本章概要 → 章首引子（50–150字）→ 正文 → 章节备注（伏笔标记、新名词登记）。

### 1.4 质量规则

- **写前必读顺序**：大纲本章行 → 设定词典 → 出场人物档案 → 上一章结尾500–800字 → 文风基准段落；"动笔前最后读到的必须是正文语态文字"。
- 正文：每章3000–5000字；≥2个张力波峰；连续500字无冲突须引入新张力；对话≥30%且有潜台词；≥1个出乎预期的转折；人物言行符合档案。
- 新名词首现须给"类别+可感知特征"，不得超出"读者已知"，到计划章节必须兑现。
- 去AI味：消除高频词（"此外""彰显""不禁""仿佛"），不连用两个以上四字成语。
- 字数用 `check_chapter_wordcount.py` 统计（去Markdown后数汉字）。
- **局限：Phase 4 只查文件存在与字数，无语义一致性评审**——这正是 WordHub 评审 Agent 的价值。

### 1.5 写作模式与续写

- 串行：主Agent循环认领下一个 pending 章节。
- 子Agent并行：每5–8章一批，只改自己负责的章节状态。
- Agent Teams：TeamCreate + TaskList，按 owner 认领，SendMessage 协调。
- 续写：章节状态机 pending → in_progress → completed/failed；从首个 in_progress/failed 恢复；JSON损坏时从大纲摘要区和文件字数重建。**已知缺口：标题只在对话上下文，Phase 2 前中断会丢失。**

## 二、纲领 Agent 提问流程设计【议】

**通用骨架**：快捷提取（首句/上传材料）→ L1必答3–5题 → 摘要 → L2可跳过/随机 → 完整配置确认 → 生成产出物 → **评审预检** → 用户二次确认 → 写入状态JSON（含标题，全部持久化）。偏好按"用户 × 文体"记忆；产出物 JSON + Markdown 双份，供观察者与评审读取。可借鉴 STORM 的**多视角问询**（由不同"读者/审稿人视角"各提一问）补充遗漏。

### 2.1 小说版

- **L1**：篇幅档位（短篇1–3万字按场景 / 中篇 / 长篇按卷→章）；题材与一句话梗概；主角及关键配角；核心冲突与驱动力。
- **L2**：世界观与规则（如力量体系上限）；视角与基调；主题；目标平台与读者（番茄/起点/出版/投稿）；风格参考（可上传样章直接作基准段落）；章数与每章字数；必含/禁写；结局倾向；是否需要人工审批核心剧情节点。
- **产出**：skill 四件套 + **伏笔/悬念台账**（埋设章、回收章、状态）+ **时间线** + **人物状态随章节生效表**（参考 Novelcrafter Progressions）。人物档案与设定词典直接初始化观察者图谱。

### 2.2 科研论文版

- **L1**：论文类型（原创/综述/系统综述/短文/学位论文章节）；目标期刊/会议与格式（字数、引用样式 GB/T 7714 / APA / IEEE、LaTeX 或 Word）；研究问题 + 一句话核心贡献 + 2–3条贡献点；**证据边界**（上传数据、结果、图表、文献库，并声明只有这些可作事实来源）。
- **L2**：必引文献与竞争工作；方法细节；报告规范（PRISMA、CONSORT）；图表清单；局限与伦理；写作语言；截止日期；期刊AI使用披露要求。
- **产出**：IMRaD 大纲（每节"要点 → 证据 → 引用"）；**论断台账**（claim ID、支撑来源、核验状态）；术语与符号表（接概念图谱）；bib库；写作计划JSON（各节字数预算/状态）；投稿前检查清单。

### 2.3 基金申请书版（NSFC 2026版）

**已核实变化**：
- 基金委 2025-12-30 发布"瘦身提质"改版：面上项目与青年科学基金C类正文改为**立项依据、研究内容、研究基础三部分**；研究内容"不再预设提纲限制"；正文原则上**不超过30页**。[NSFC官网](https://www.nsfc.gov.cn/p1/3381/2821/99242.html)【实】
- 2026版提纲提示语【二手，与官网口径一致】：（一）立项依据——为什么开展、科学技术价值；（二）研究内容——按研究自身逻辑撰写，应提炼特色与创新、年度研究计划；（三）研究基础——研究基础与可行性分析（含风险应对）、工作条件、正在承担的相关项目、完成NSFC项目情况；（四）其他需要说明的情况——**第5条要求详细说明撰写中使用生成式人工智能的位置和内容**。
- 面上4年；青年C类3年、经费包干、年龄限制（男<35、女<40）；均需选研究属性（自由探索/目标导向）。
- 2025版旧六段式提纲（立项依据 / 研究内容目标与关键科学问题 / 研究方案与可行性 / 特色与创新 / 年度计划与预期结果 / 研究基础与工作条件）**已停用**。
- 2027年度模板截至今日未发布（往年约12月–次年1月）→ **模板必须做成可更新配置，不写死**。

**提问清单**：
- **L1**：项目类型（切换模板）；申请代码与研究属性；一句话核心科学问题 + 项目名称草案；前期基础（代表作、预实验数据）。
- **L2**：国家需求/学科前沿；关键文献与研究空白；研究目标与2–3个递进的研究内容；关键科学问题（提示区分"科学问题"与"技术问题"）；方法与技术路线；预期成果；创新点（≤3）；风险与应对；平台条件；在研/结题项目；同年其他申请。

**产出**：三部分正文骨架 + 30页预算；**逻辑一致性矩阵**（目标 ↔ 内容 ↔ 关键问题 ↔ 方案 ↔ 预期成果 ↔ 年度计划；新提纲虽取消小标题，评审仍用它内部核对）；**AI使用台账**——自动记录各Agent生成/改写了哪一节哪一段，直接生成第（四）部分第5条披露文本。**这是很强的差异化功能**，且同样适用于期刊的AI披露要求。

## 三、小说工具的一致性机制

- **Sudowrite**【实】：Story Bible（梗概、文风、角色、世界观、大纲、场景），生成时自动读取；可按卡片/特征对AI隐藏；正文中识别到的设定元素加下划线；Chapter Continuity 最多回读25章/2万词；系列共享设定；Act → Chapter → Scenes。
- **Novelcrafter Codex**【实】：条目有别名与排除词，正文自动检测，注入策略"检测到才注入/总是/从不"；Mentions 出场热力图；**Progressions**——设定变化挂在具体场景上，AI只在写该场景及之后时看到；**Matrix**——条目×场景矩阵发现穿帮。[docs](https://www.novelcrafter.com/help/docs/codex/progressions-additions)
- **NovelAI Lorebook**【实】：关键词/正则触发、多关键词组合、常驻、级联激活；每条Token预算、插入顺序与位置；**Context Viewer** 回放上下文拼装。[docs](https://docs.novelai.net/en/text/lorebook/)
- **国内**：阅文"作家助手"——角色/设定高亮、"问全书"附原文片段、"对照写"【实】；蛙蛙写作——续写自动提取总纲/章纲/前文【实】，用户反馈"人物提前登场"【二手】；笔灵——总纲→分卷→细纲→逐章，"编辑视角"审稿【官网宣传】；炼字工坊——"知识库一致性校验"【宣传未验证】；彩云小梦——设定词条+人物状态【二手】；番茄平台2026年在治理低质AI内容【二手】。

**借鉴【议】**：统一设定库（别名、注入策略、预算优先级）；设定按章节生效；上下文查看器；出场矩阵；带原文引证的全书问答。

**差异化【议】**：竞品设定基本靠作者手动维护。WordHub 可让观察者每章写完自动抽取新事实形成"待确认变更"，确认后写回图谱并标生效章节；评审用图谱做硬校验（已死角色出现、地点/时间冲突、能力越界、称谓不一）；图谱随章节回放并与大纲联动；保留"核心剧情人工审批"节点以符合平台合规。

## 五、学术研究对角色分工的启示【实】

**纲领**
- STORM（NAACL 2024）：多视角模拟问答再生成大纲，组织性+25%。[2402.14207](https://arxiv.org/abs/2402.14207)
- Co-STORM：用户随时插话，讨论实时整理为共享思维导图 → 观察者图谱可充当此导图。[2408.15232](https://arxiv.org/abs/2408.15232)
- DOC（ACL 2023）：详细分层大纲 + 控制器；连贯性+22.5%、大纲相关性+28.2%。[2212.10077](https://arxiv.org/abs/2212.10077)
- DOME：大纲随写作动态修订，时序知识图谱检测冲突。[2412.13575](https://arxiv.org/abs/2412.13575)

**写手**
- Re3：每步重新注入计划与故事状态，再重排/编辑。[2210.06774](https://arxiv.org/abs/2210.06774)
- **Agents' Room**（ICLR 2025）：按叙事理论拆子任务给专职agent，优于单agent——直接支持分角色架构。[2410.02603](https://arxiv.org/abs/2410.02603)
- Dramatron（CHI 2023）：逐层生成、每层可人工编辑。[2209.14958](https://arxiv.org/abs/2209.14958)
- StoryWriter：先生成事件因果图并校验再写。[2506.16445](https://arxiv.org/abs/2506.16445)
- Lost in the Middle：长上下文中段利用最差 → 约束放提示首尾。[2307.03172](https://arxiv.org/abs/2307.03172)

**评审**
- CoVe：核验问题须独立回答。[2309.11495](https://arxiv.org/abs/2309.11495)
- FActScore / SAFE：原子事实逐条核验。[2305.14251](https://arxiv.org/abs/2305.14251)、[2403.18802](https://arxiv.org/abs/2403.18802)
- **ConStory-Bench**（2026）：一致性错误5类19子类（时间线、人物塑造、基本事实、常识、风格），错误集中在故事中段 → 可直接作评审清单。[2603.05890](https://arxiv.org/abs/2603.05890)
- SCORE：物品状态追踪 + 章节摘要 + RAG 检测矛盾。[2503.23512](https://arxiv.org/abs/2503.23512)
- ConWriter（2026）：每个场景转移即校验并局部修复，防错误后传 → **每章校验，不等全书写完**。[2608.05169](https://arxiv.org/abs/2608.05169)
- NstAgent（2026）：叙事状态中维护"未来要求"。[2609.35759](https://arxiv.org/abs/2609.35759)
- MAGNET/ATLAS（2026）：逐场景图比对，幻觉减少45–50%。[2607.00918](https://arxiv.org/abs/2607.00918)

**评审机制**
- AI Scientist v1/v2：自评偏乐观，需外部/人工抽检。[2408.06292](https://arxiv.org/abs/2408.06292)
- **AgentReview**（EMNLP 2024）：评审偏见使37.1%录用决定改变 → 多评审独立、匿名。[2406.12708](https://arxiv.org/abs/2406.12708)
- WritingBench：按需求动态生成评分标准 → 评审 rubric 从纲领自动派生。[2503.05244](https://arxiv.org/abs/2503.05244)
- Agent Laboratory：每阶段引入人类反馈显著提高质量。[2501.04227](https://arxiv.org/abs/2501.04227)

## 六、综合建议【议】

1. **纲领**：分层问答 + 快捷提取 + 配置确认 + 多视角问询；产出事件图/逻辑矩阵后先交评审预检，再交用户确认；状态全持久化。
2. **写手**：按章/节写；注入顺序"约束 → 设定 → 前文结尾 → 文风锚点"（最后读正文语态）。
3. **编辑**：只管文本、语法、格式、字数、引用格式；Self-Refine 式低成本自修；**与评审职责严格分开**。
4. **评审**：原子事实核验、核验问题隔离回答；小说用 ConStory 分类清单，论文/基金用论断台账 + 逻辑矩阵；每章立即校验，中段加力；多评审独立；保留人工抽检。
5. **观察者**：维护带时间维度的人物/物品/事件/概念图谱，变更需作者确认，作为评审的事实底座；基金场景下同时维护AI使用台账。
6. **自建Agent**：可视化声明读写哪些图谱/设定、上下文预算，支持导入导出与共享。
