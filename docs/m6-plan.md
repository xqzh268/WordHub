# M6 参考库与图谱：范围与计划

更新日期：2026-11-04。依据：[research/graph-design.md](research/graph-design.md)、[research/documents-references.md](research/documents-references.md)，以及 10-21 确认的顺序（M5 之后做参考库与图谱）。**小说先行**，科研 References（Zotero/Crossref/CSL）和科研图谱仍按既定放在 P4。

## 为什么分两步、各做到哪

> **范围调整（2026-11-04）**：用户明确要求图谱可交互——点人物看详情、以人物身份接受采访、按整个图谱推演走向。因此下表里“不做”的“节点采访”和“推演”已经纳入 M6.2，拆成 M6.2a（图谱视图）、M6.2b（人物采访）、M6.2c（推演），均已实现，见 [m6-progress.md](m6-progress.md)。分支/多世界“并入正史”仍然不做：推演只存为非正史参考。

| 阶段 | 做 | 不做（留给后续） |
|---|---|---|
| **M6.1 参考库** | 导入参考小说/资料（TXT、Markdown、EPUB、DOCX、有文本层的 PDF）→ 本地解析成按章文本 → 阅读器 + 全文检索 → 选段「提问 / 作为文风示范 / 复制引用」→ Agent 可用 `reference.search` / `reference.read` 查阅 → 文风示范注入写手上下文（兑现 10-22 的决定） | MOBI（foliate 在渲染端可解析，但没有可复现的样本与验收）、扫描 PDF 的 OCR、DRM 书（明确拒绝，不去 DRM）、EPUB CFI 级定位、科研文献（Zotero/Crossref/CSL） |
| **M6.2 图谱** | 史官定稿时抽取**人物关系**（带逐字原文锚点）→ 用户在事实页确认 → 图谱视图（人物为节点、关系为边）+ **时间滑块**（按章节揭示点过滤，兼防剧透）+ 节点详情（人物状态、关系、原文出处，可跳到章节） | **节点采访（角色扮演对话）**、**推演/分支**、Sigma 大图、别名时效合并的完整本体、科研图谱视图。这些是 graph-design 里体量最大的部分，数据模型先为它们留好字段（`revealed_at`、`status`、`asserted_by`），但不在这一轮做 |

## 方向修订：参考库做成"书架"+ 文献管理器（2026-11-04，用户提出）

项目以后要扩展到论文、基金和办公材料，参考库因此不只是"导入后能读"，而是要有书架的产品形态和文献管理器的能力。**M6.1（本轮已做）是它的底座**：导入与解析、按章文本、阅读、全文检索、选段锚点、Agent 查阅工具、文风示范。在此之上分三层往上长：

| 阶段 | 内容 |
|---|---|
| **M6.1b 书架形态（已完成，2026-11-04）** | 书架视图（封面网格 ⇄ 列表，封面取自 EPUB，没有就生成）；排序与筛选（最近导入/最近阅读/书名/作者/年份/格式）；**标签、收藏、文件夹式分组（集合）**；阅读进度与"在读/读完"；可编辑的元数据（标题、作者、年份、出版方、类型、DOI/ISBN、备注）；重复检测（同一本的不同文件）；**批注与高亮**（锚点同选段，单独存 `annotations.json`，可导出） |
| **M6.3 文献能力** | BibTeX / RIS / CSL-JSON 导入导出；按 DOI / ISBN 联网补全元数据（需要用户明确同意联网，只发标识符，不发正文）；**引用样式（CSL）渲染**与"插入引用"到正文，引用键稳定；PDF 原样阅读（按页渲染、页码锚点、选区高亮）；跨库全文索引（FTS）提速；撤稿/许可证提示等科研特有项放 P4 |
| **办公材料** | 把 Word/PPT/Excel 导出的文本也纳入书架（先支持 DOCX，PPTX/XLSX 视需要）；与基金申请书的"逻辑一致性矩阵"、论文的参考文献表联动 |

**数据模型怎么为它留空间**：`reference.json` 已带 `schemaVersion`（现为 1），以后只增字段不改旧字段，读取端容忍缺失；标签/集合放库级的 `.wordhub/references/library.json`（一份索引，随时可从各书目录重建），批注放每本书目录下的 `annotations.json`；原件、解析文本、元数据仍在各书自己的目录里，整个 `.wordhub/references/` 复制走就是完整的书架。

**顺序**：图谱（M6.2）是小说场景的能力，书架是论文/基金场景的地基，且你这次明确强调了书架，所以建议**先做 M6.1b，再做 M6.2 图谱**；需要的话可以对调。

## 已定约束（不重新讨论）

- 用户可读的稿件与设定放写作文件夹，SQLite 事件日志放应用数据目录；Markdown 为真相源。
- 参考库原件与解析文本放在项目的 `.wordhub/references/<id>/`（原件副本、`reference.json`、按章 `text/NNNN.txt`），不上传；**只有选段提问时所选文字才会发给用户配置的模型服务商**，界面要明说。
- 图谱里只有**用户确认过的**关系才算数；`proposed` 的以虚线淡色显示，评审/采访只认 `confirmed`。
- 不提供去 DRM；扫描 PDF 明确报"没有文本层"，不做 OCR。
- 每个阶段照既有门禁：单测、Electron 端到端（含版面断言）、真实 deepseek-flash 验证、推送后看 CI、文档如实写未验证项。

## M6.1 设计要点

- **解析**：TXT 先严格 UTF-8、失败回退 GB18030；按"第N章/回/节、楔子、序章、后记、番外、Chapter N"切章，找不到章标题就按约 8000 字在段落边界分块。EPUB 用 jszip 读 OPF/spine/目录，jsdom 取正文；拒绝带非字体加密的（DRM）。DOCX 读 `document.xml` 段落，Heading 样式作章标题。PDF 用 pdfjs-dist 取文本层，按页聚合成章；没有文本层则报错。
- **安全上限**：压缩包解压总量与条目数上限、单本文本字数上限、PDF 页数上限；文件路径只来自系统对话框。
- **锚点**：`{ref, chapter, start, end, quote}`，用时校验 quote 与原文一致，对不上就明说，不静默指向别处。
- **Agent 工具**：`reference.search`（关键词，返回出处与片段）、`reference.read`（章节或区间）。只读；需要 Agent 声明工具并在 `memoryScopes.read` 含 `references`。自建 Agent 表单同步增加。
- **文风示范**：作者选段 →"作为文风示范"写入 `.wordhub/bible/style-samples.md`（走受控写盘，记为用户修订，可撤销）→ 作为独立上下文层注入写手/编辑/纲领；最多 5 段、每段 ≤ 600 字，提示词明确"只学笔法与节奏，不得照抄情节与句子"。

## M6.2 设计要点

- 事实种类新增 `relation`（主体、对象、关系、逐字锚点）；史官提示词与 `fact.propose` 同步扩展，沿用事实页的确认/驳回与事件日志。
- 图谱是**投影**：从已确认的 `character_state` / `relation` 事实与章节摘要推出节点和边，`revealed_at` = 事实所在章号。不另建一套可手改的图数据，避免与事实表两份真相。
- 视图：React Flow 做结构化关系图（人物卡片节点），布局用 elkjs 或简单力导；时间滑块 = 章号；节点详情面板。人物规模按 50–500 估，首版不上 Sigma。

## 验收线

- M6.1：五种格式各有真实样本（含中文 PDF 由 Chromium 生成）导入成功；DRM EPUB 与无文本层 PDF 被明确拒绝；检索/阅读/选段三个动作端到端通过；真实模型用 `reference.search`/`reference.read` 找到并引用样本里的句子；文风示范层出现在写手上下文清单里。
- M6.2：带关系的样章经史官抽取、确认后出现在图上；时间滑块拖到更早章节时后来才揭示的关系消失；未确认关系不进入图（或以虚线区分）；节点详情的原文出处能对上章节。
