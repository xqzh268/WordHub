# M3 当前进度

日期：2026-10-05

本轮先完成M3.0和M3.1的可复用地基，并把M2.1遗留项接到产品链路：

- Electron worker现在只做消息路由，运行入口是`executor.ts`外观，主循环、Pi主机、审批恢复和请求分发分别位于`packages/runtime/src/runs/`与`packages/runtime/src/host/`，每个模块控制在300行以内。
- faux运行和真实运行共用同一套Executor接口；主模型故障会产生`run.fallback`，且已有工具副作用时不会重复从头运行备用模型。
- 审批事件包含相对路径、字数和粗粒度行差异；权限拒绝产生确定性的群聊提示，重载后工具保持中文标签。
- `tasks`和`run_snapshots`已加入SQLite迁移。任务图、声明式工作流校验、工作流运行器、费用估算均为纯runtime模块并有单测。
- 审批快照包含Pi消息、系统提示、模型引用和待执行工具调用；有快照的等待审批运行不会在启动时被清扫。恢复批准通过主进程凭据解析传入保存的密钥，按快照重放原工具调用并继续写盘；无快照的旧运行仍会被标记为中断。
- 运行前会显示输入、输出和费用预估；单次运行不设硬预算上限。原“章节定稿后自动评审”开关已移除，待定稿动作真正存在后再设计。
- 真实模型回归工作流现为手动触发；缺少`DEEPSEEK_API_KEY`时本地可跳过，显式设置`WORDHUB_REQUIRE_LIVE=1`则失败。
- M3第1步已接入产品运行：未@消息会按意图路由到`write-chapter`（写手→编辑）、`review-only`或显式全流程；每个节点有独立任务和Agent运行，父运行持久化工作流定义与整体费用预估。
- M3第2步已贯通质询：两轮仍未解决时产生`escalation.created`并暂停节点，界面显示真实质询线程和裁决卡，裁决写入`escalation.resolved`并继续工作流。
- M3第3步已加固写盘队列：同一受控产物并发提交时第二个Agent自动保留为候选副本，双方内容均可追溯；已有外部修改守卫继续生效。
- M3第4步已接入群聊：任务进度、工作流预估、会话用量汇总、“请评审当前章节”和中断运行“继续运行”均使用真实状态。
- M3第5步已加入手动真实回归脚本和GitHub workflow，覆盖《长安夜》矛盾、质询升级、裁决和返工；脚本会从Windows用户/机器环境补取密钥并显式传给Electron子进程。

已验证：`validate:schema`、`typecheck`、`npm test`（8个测试文件、33项）、`test:m2:faux`（5项）、`lint`、桌面构建、桌面冒烟、布局检查和M1重启E2E（16/16，含审批强杀重开恢复）。确定性测试覆盖恢复时注入密钥，以及缺密钥时写入`run.error`且不产生审批裁决事件；M1脚本在测试进程中移除`DEEPSEEK_API_KEY`。

已验证：新增`product.test.ts`覆盖写手→编辑的任务顺序、产物传递和费用用量，以及质询两轮升级、裁决后继续；新增并发写盘测试确保两方内容都保留。真实模型E′已由上一轮验收以22/22通过；完整M3真实回归保持手动触发，待有密钥时运行`npm run test:m3:live`。

## 本轮修复复核（2026-10-05）

- Electron子进程不再依赖继承到的进程环境：主进程和回归脚本会按“加密保存凭据→`DEEPSEEK_API_KEY`→`WORDHUB_DEEPSEEK_API_KEY`→Windows用户/机器环境”解析，并显式传给worker。截图中的401来自旧版PowerShell环境变量读取命令返回错误文本，已改为WindowsPowerShell和pwsh均兼容的读取方式；密钥值不写日志。
- 质询后续节点现在直接注入线程ID、主张、证据和前序回复，写手不再靠`history.search`猜线程。协调器固定创建“回应→复核→回应→最终复核→返工”节点；最终复核后仍有未解决的blocking线程时自动生成裁决卡，裁决后返工节点才可调度。
- 目录传给`doc.read`或`bible.read`时返回清单，减少模型猜不存在文件导致的工具轮数耗尽；写手和评审提示明确要求以清单和当前任务为准。成功写入后不重复写入。
- 对话Agent消息改为安全的轻量Markdown渲染，支持粗体、行内代码、标题和有序/无序列表；不使用HTML直插。
- `product.test.ts`新增固执写手的确定性两轮质询→裁决→返工测试；当前确定性测试为39项。真实运行已观察到实际DeepSeek评审指出左右手矛盾、质询回复、章节落盘和无矛盾章节的“无矛盾”结论；真实回归脚本仍需在有密钥环境完成完整收尾后再标记通过。
