## 三、缺陷清单

| # | 严重度 | 事项 | 证据与成因 |
|---|---|---|---|
| Q1 | **高** | 升级裁决后，工作流永不结束 | 失败现场（我保留了数据库）：`challenge-reply-2` 任务停在 `waiting_approval`，其运行 `waiting_approval`，父运行 `running`；事件 1692 `escalation.resolved` **早于** 1927 `run.waiting_approval`。成因在 `runs/live.ts` 约 239 行：节点运行结束时用 `escalated = 存在 escalation.created` 判断是否暂停，**没有检查它是否已被裁决**，裁决先到时任务仍被暂停，没人再唤醒。这不是脚本的瞬间点击造成的假象：写手那一轮在升级之后还继续生成了数分钟，用户在这段时间裁决就会触发 |
| Q2 | 中 | 回归脚本仍有“带路” | 首段提示词写了“让评审核验……左右手矛盾”，设定集写着“评审必须检查左右手矛盾”；误报测试的提示词要求“若一致，不要调用 `challenge.raise`”，测的是听不听指令，不是判断力。纸面断言只等 `paper-sheet`，空纸面也有该元素。失败时不清理临时目录。我新增的 `m3-live-neutral.mjs` 是不带路的度量 |
| Q3 | 低 | 纸面里“第一章”重复三次 | 页眉、章号、标题各出现一次 |
| Q4 | 低 | 报告里的一处表述不准 | “主进程会读取 Windows 用户/机器环境变量”：产品代码只用进程环境变量，读取注册表只出现在测试脚本里，不影响产品 |

## 四、评审质量评测（新增）

[scripts/m3-live-neutral.mjs](../scripts/m3-live-neutral.mjs)（`npm run test:m3:neutral`）：设定集只写事实（“裴照是左撇子，惯用横刀”），提示词只说“请评审第三章 / 第四章”，每次一个全新项目，重复 3 次；第三章预埋“右手按刀”，第四章无矛盾。

| 轮次 | 矛盾章 | 无矛盾章 |
|---|---|---|
| 第一批（3 次） | 3/3 指出左右手矛盾 | 2 次无质询；**1 次质询是“第四章与第三章逐字相同”**——这是我的测试设计缺陷：评审流程已把第三章改成“左手”，与我写的第四章重复，评审的观察是对的 |
| 修正后重跑（3 次，第四章内容独立） | **3/3** | **0/3 误报** |

结论：评审在**不被提示要找什么**的情况下，6 次全部指出预埋的左右手矛盾，且质询正文引用了设定原文，质量达标；无矛盾章节未出现误报。通过线定为检出 ≥ 2/3 且误报 ≤ 1/3。

另：整个质询回合在真实模型下确实走通了——写手 `v4-pro/high` 先“部分接受”，评审 `v4-pro/max` 复核后再次质询，第二轮仍分歧升级，裁决后返工把章节改成“左手”。

### 第二步：M4 小说流程（约 14 个工作日）

M3 收口后进入 M4。目标：**从一个空项目开始，用户只回答问题，就能写出前三章，并且设定一致性有保障。**

| 阶段 | 内容 | 验收 |
|---|---|---|
| M4.1 纲领问答（2 天） | 在群聊里用结构化表单卡做分层提问（L1 必答：题材梗概、主角、核心冲突；L2 可跳过或随机：世界观、视角基调、主题、读者、章数、必含 / 禁写）；支持首句快速提取、“回到某题”修改；偏好按“用户 × 文体”记忆。产出：人物档案、大纲、设定词典、文风基准、写作计划 JSON，经你确认后写入 `.wordhub/bible/` | 从一句话开始走完问答，生成文件，重启后可续问 |
| M4.2 上下文升级（2 天） | 按固定顺序注入：本章大纲行 → 设定词典 → 出场人物档案 → 上一章结尾 500–800 字 → 文风基准段落；带 token 预算与溢出裁剪；“查看上下文”逐层展示 | 清单与实际请求一致（faux 抓取请求） |
| M4.3 编辑清单（2 天） | 确定性检查工具：字数、AI 腔词表、对话占比、连续四字成语；加语言润色。评审与编辑职责严格分开 | 检查工具有单测；编辑只改文字，不改情节 |
| M4.4 评审清单（2.5 天） | 按一致性错误分类（时间线、人物塑造、基本事实、常识、风格）逐类核验；核验问题隔离作答；质询引用设定原文与出处；每章写完立即评审 | 用预埋多类矛盾的样例，检出率与误报率入评测 |
| M4.5 观察者与事实表（2.5 天） | 每章定稿后抽取人物状态、新名词、伏笔，写成“待确认”事实；“事实”页签展示、你来确认或驳回；评审用已确认事实做硬校验 | 确认后的事实能让评审抓出跨章矛盾（例如第 5 章死者在第 8 章出场） |
| M4.6 定稿动作（1.5 天） | “定稿”按钮：触发观察者抽取、追加章节摘要；此时才恢复“定稿后自动评审”开关（默认关闭） | 定稿 → 抽取 → 可选评审 的链路可回放 |
| M4.7 真实回归（1.5 天） | 全新项目：一句话 → 问答 → 前三章；预埋跨章矛盾；记录费用、耗时、检出率、误报率；纳入夜间回归 | 全流程通过，指标写入报告 |
